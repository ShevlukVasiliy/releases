# Архитектура

Releases — локальный процесс. Flask обслуживается Waitress и слушает только `127.0.0.1`. Сервер запускается без сетевой инициализации и полного сканирования. Изменяющие запросы требуют точного локального `Host`, `Origin` и случайного токена текущего процесса. Это защита локального интерфейса, а не механизм удалённого доступа.

Состояние хранится в SQLite вне проекта. Версия схемы задаётся `user_version`. Один экземпляр на каталог данных обеспечивается блокировкой `filelock`. Очередь выполняет одну задачу за раз; незавершённые задачи после перезапуска помечаются прерванными без автоматического повтора. Частичные результаты проверки артистов сохраняются. Повтор для операций с файлами или Music требует проверки состояния.

## Индекс

При сканировании аудиофайлов метаданные читаются через Mutagen. Для неизменённых файлов используются записи с совпадающими путём, размером и временем модификации; содержимое, изменённое с сохранением этих признаков, не обнаруживается. Обход файловой системы выполняется целиком. Индекс обновляется транзакционно после успешного обхода, при ошибке прежний индекс сохраняется. Файлы с ошибкой чтения повторно читаются при следующем сканировании. Удалённые файлы удаляются из индекса.

## Проверка и загрузка

Клиент `yandex-music` изолирован в адаптере каталога. Артисты проверяются последовательно; ошибка одного не останавливает остальных. Дискографии кэшируются на сутки, автоматические успешные сопоставления — на 30 суток, неудачные — на сутки; ручные сопоставления не истекают. Алгоритм нормализации и сравнения может давать ложные совпадения; точность на размеченной выборке не проверялась.

Загрузки выполняются в очереди. Сначала создаётся временный файл в папке назначения, затем он размечается тегами и публикуется без замены существующего имени. Успешно скачанные треки сохраняются и при частичной ошибке альбома. При повторе существующие файлы пропускаются. Полная загрузка с реальным аккаунтом ещё не проверена.

## Music и обслуживание

Импорт через AppleScript передаёт файлы приложению Music, оставляя исходники на месте. Для подтверждённых файлов сохраняются persistent ID и путь Music. Перед вызовом создаётся запись о попытке; неопределённый результат не повторяется автоматически во избежание дубликатов. Если копирование в настройках Music отключено, приложение может ссылаться на исходник. Сервис не меняет настройки Music и не гарантирует облачную синхронизацию.

Проверка тегов работает на временных копиях файлов из папки загрузок. Перед записью показывается список изменений; изменившиеся после просмотра файлы пропускаются, рядом с изменяемыми создаётся резервная копия. Для порядка треков Music сверяет идентификатор, метаданные и старые значения перед записью. Для обеих операций применение запускается отдельно от предварительной проверки. Интеграция с настоящей библиотекой Music ещё не проверена.

## Учётные данные и перенос

`keyring` использует системное хранилище macOS или Windows. Токен не возвращается API и не записывается в SQLite. Приоритет: токен из хранилища, переменная окружения, прежний файл. Подлинность при сохранении не проверяется. На Windows работа ещё не проверена.

Перенос старых исключений и успешных сопоставлений запускается вручную после сканирования. Исходные файлы не меняются, существующие сопоставления не перезаписываются. SQLite, файлы медиатеки и токены не входят в репозиторий.
